# EP-03 local transport (US-013)

US-013 adds an Electron-main ingress capability for the fixed three-agent MVP. The capability is not started by ordinary `npm run dev`. US-015 starts it only for `npm run dev:simulated` and passes its launch credentials to one owned simulator child over private stdin. No provider adapter, preload API, renderer store, or Phaser mapping is part of US-013.

## Ownership and trust boundary

Electron main owns the Node `net` server, accepted sockets, per-run secret, validation, recent-event cache, and minimal current-state mirror. It listens on IPv4 `127.0.0.1` with port `0`, then receives the OS-assigned port. A 32-byte `randomBytes` token is generated for each ingress lifetime and represented as 64 lowercase hexadecimal characters. The only token handoff is the main-process-only launch callback intended for US-015's owned child; `start()` returns only host and port. `readCurrent()`, subscriptions, diagnostics, preload, and renderer never receive the token. The endpoint and token are never logged. Main compares a valid-format candidate using `timingSafeEqual`.

At most four unauthenticated sockets can await a hello, each with a five-second timeout. An authenticated socket must send its snapshot within five seconds. Only one authenticated Connector socket may own the session at a time. Rejected input closes its socket. On shutdown, main waits for any pending listen attempt, destroys every owned socket, closes the listener, clears the dedup cache, and zeroes the token buffer. Each ingress instance is single-use: calling `stop()` before or after `start()` permanently prevents another start on that instance. US-015 wires this lifecycle into the simulated development app and child process; US-017 will complete user-visible reconnect behavior.

## Wire protocol, version 1

Each message is one UTF-8 JSON object followed by a single LF byte (`0x0a`). TCP reads may split or combine frames; the decoder accumulates until LF and processes complete frames in arrival order. Blank frames, CR, malformed JSON, and invalid UTF-8 are rejected. A frame may contain at most **16,384 bytes before LF**. The limit applies while buffering as well as after a complete frame; an over-limit frame closes the socket. No raw input or credential value is included in diagnostics.

The only valid sequence on one socket is:

1. `hello`: `{"kind":"hello","version":1,"token":"<64 lowercase hex>","source":{"kind":"local-connector","instanceId":"sim-1"}}`. Before a valid hello, every other message is rejected. Main returns `{"kind":"hello-accepted","version":1}` on success. Wrong token, version, shape, or a second authenticated socket is rejected. A repeated hello is invalid.
2. `snapshot`: `{"kind":"snapshot","version":1,"source":{"kind":"local-connector","instanceId":"sim-1"},"agents":[...]}`. `agents` contains **exactly one** state for each of Ari, Mina, and Sol. Its source must match the authenticated hello. Main atomically replaces its mirror, advances its local revision, and returns `{"kind":"snapshot-accepted","version":1,"revision":N}`. Events before the snapshot, missing or incomplete snapshots, and a second snapshot on the same session are rejected.
3. `event`: `{"kind":"event","version":1,"event":{...}}` containing one `agent.state.changed` application event. It is accepted only after the initial snapshot, with source matching the hello. Valid, non-duplicate events update one mirrored agent and advance revision in arrival order. Timestamps are diagnostic, never an ordering authority.

Every message and nested object rejects unknown fields. IDs (`source.instanceId` and `event.id`) are 1–64 ASCII characters matching `[A-Za-z0-9][A-Za-z0-9._:-]*`. The event timestamp is a real, canonical UTC ISO-8601 time with millisecond precision (`YYYY-MM-DDTHH:mm:ss.sssZ`). The only event type is `agent.state.changed`; lifecycle state remains `idle | working | waiting | completed | error`. Agent identity must exactly match one of `mock-agent-ari`/`Ari`, `mock-agent-mina`/`Mina`, or `mock-agent-sol`/`Sol`. Activity is mandatory, 1–512 UTF-8 bytes, and may not contain control characters or leading/trailing whitespace. Optional reason is `approval_required` or `capacity_exhausted`. These runtime rules apply to snapshot states and event payloads. The shared TypeScript contract alone is not treated as validation.

## Identity, deduplication, and synchronization

`source.instanceId` names the Connector event namespace; `event.id` names an event within it. Main keeps at most 4,096 `(instanceId,eventId)` keys in insertion order. Duplicate arrivals do not refresh recency or mutate state. Once full, accepting a new key evicts the oldest accepted key. The cache survives socket loss and reconnect during one ingress lifetime and clears on ingress stop. A new `instanceId` can reuse an event ID. This is bounded recent deduplication, not durable replay protection.

Main assigns a separate internal `sessionId` to each authenticated socket. The Connector supplies neither session ID nor revision. The mirror holds the latest complete three-agent state, connection phase, session ID, and monotonic revision. A complete snapshot atomically replaces the mirror and advances revision; a valid non-duplicate event advances it again. Rejected, invalid, and duplicate messages do not advance it. On disconnect, main retains the last valid agents and marks the phase disconnected. A new authenticated session gets a new internal ID; its complete snapshot replaces the prior mirror before its events are accepted. Callbacks from older sockets cannot update the active mirror. Connection-phase notifications are separate from revisioned data changes.

US-014 initializes a newly loaded renderer by subscribing before reading `readCurrent()` in the same main-process turn, then uses the returned revision and session ID to reconcile queued changes. The renderer never uses a stale snapshot to overwrite a newer event or restore an older connection phase. The fixed IPC bridge projects trusted state without credentials or event-envelope metadata; the reducer accepts complete three-agent mirrors and handles revision gaps without replay. US-017 will verify reload, loss, restart, and resynchronization behavior end to end.

Sol's existing coffee-break animation is simulation presentation. US-015's deterministic sequence and US-016's presentation adapter must select it explicitly for the scripted Sol activity. Generic `idle` or `waiting` must never imply coffee-break presentation, and no `break` lifecycle or coffee-specific application-event field is added.
